早期的设计转代码工具把画板翻译成一堆绝对定位的 div，看着对，却没法维护。新一代工具不一样，比如 Figma 的 Dev Mode MCP Server 和 Builder.io 的 Visual Copilot：它们读取结构和变量，再映射到你已有的代码。

该喂给 Agent 什么

  • Token：导出成 CSS 变量，颜色就会映射成 var(--accent) 而不是硬编码色值。
  • 组件注册表：比如 shadcn registry，这样"按钮"就是你自己的 Button。
  • 设计稿里用自动布局：没有 auto-layout 的画板，模型只能猜 flex 规则。

我们的看法

把生成的代码当成新人提的 PR：看起来没问题，但边界状态缺失。一定要检查空、加载、报错、超长文本这几种状态，再做一遍无障碍检查。先把注册表建好的团队，之后每一次生成都在复利。

Early design-to-code tools translated frames into absolutely positioned divs. They looked right and were unmaintainable. The current generation, Figma's Dev Mode MCP server and Builder.io's Visual Copilot among them, works differently: it reads structure and variables and maps them to code you already own.

What to feed the agent

  • Tokens exported as CSS variables, so colours map to var(--accent) instead of hex.
  • A component registry, for example a shadcn registry, so "button" means your Button.
  • Auto-layout in the file. Frames without it force the model to guess flex rules.

Our take

Treat generated code as a pull request from a junior: correct-looking, missing edge states. Always check empty, loading, error and long-text states, and run an a11y pass. Teams that publish a registry once get compounding returns from every later generation.
