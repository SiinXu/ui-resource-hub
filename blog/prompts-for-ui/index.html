"现代、简洁"对模型毫无信息量。要写清布局、token、状态、真实内容和禁区。「現代、簡潔」對模型毫無資訊量。要寫清佈局、token、狀態、真實內容和禁區。"Modern and clean" means nothing to a model. Name layout, tokens, states, content and what to avoid.「モダンでクリーン」はモデルに何も伝えない。レイアウト、トークン、状態、内容、禁止事項を書く。"모던하고 깔끔하게"는 의미가 없다. 레이아웃, 토큰, 상태, 콘텐츠, 금지 사항을 적어라."Moden dan bersih" tiada makna. Nyatakan susun atur, token, keadaan, kandungan dan larangan."Hiện đại, gọn gàng" chẳng nói gì. Hãy nêu bố cục, token, trạng thái, nội dung và điều cấm.« Moderne et épuré » ne dit rien. Précisez mise en page, tokens, états, contenu et interdits."Moderno y limpio" no dice nada. Indica layout, tokens, estados, contenido y prohibiciones.„Modern und clean“ sagt nichts. Nenne Layout, Tokens, Zustände, Inhalt und Verbote.

UI 提示词就是一份迷你设计规格。模型会用默认值填满你留下的每个空白，而每个空白最后都会变成套路。

六格模板

目标：开发者工具定价页，3 档，年付切换
布局：12 栏，最大 1200px，≥900px 三档并排，以下堆叠
Token：Geist 字体，正文 14/20，圆角 10，唯一强调色 #2563eb，中性灰
状态：hover、focus-visible 描边、选中档、按钮加载态
内容：使用下方真实文案（不要 lorem），价格 0 / 19 / 49
禁止：文字渐变、玻璃拟态、emoji 图标、全部居中

为什么有效

Vercel 的设计规范和 Rauno Freiberg 的《Interfaces》都强调小而可检查的规则：焦点状态、点击区域、等宽数字。把它们写成明确的行，产出就能被验收。真实内容也很重要，占位文字会掩盖溢出和层级问题。

我们的看法

迭代时把"禁止"一行放到最前面。模型见过坏版本后，对否定约束的服从度更高。每类组件留一份可复用提示词；UI Hub 的组件卡都带可复制的 Prompt，可以直接起步。

A UI prompt is a tiny design spec. The model fills every gap with defaults, so each gap you leave becomes a cliché.

The six-slot template

Goal: pricing page for a dev tool, 3 tiers, annual toggle
Layout: 12-col, max 1200px, tiers in a row ≥ 900px, stacked below
Tokens: Geist, 14/20 body, radius 10, one accent #2563eb, neutral greys
States: hover, focus-visible ring, selected tier, loading on CTA
Content: real copy below (no lorem), prices 0 / 19 / 49
Avoid: gradients on text, glassmorphism, emoji icons, centred everything

Why it works

Vercel's design guidelines and Rauno Freiberg's "Interfaces" both stress small, checkable rules: focus states, hit targets, tabular numbers. Turning those into explicit lines makes the output verifiable. Real content matters too; placeholder text hides overflow and hierarchy problems.

Our take

Put the "Avoid" line first when iterating. Models obey negative constraints better once they have seen the bad version. Keep a reusable prompt per component type; UI Hub's component cards include a copyable prompt you can start from.
